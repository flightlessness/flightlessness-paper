# 博客项目路线图

## 项目目标

维护 flightlessness 的中文个人博客，持续记录写作与对世界、自然、科学和生活的思考。让新增文章有清楚的写作、预览和发布路径，让访问者能通过首页、Posts、分类、标签和订阅找到内容。主分支上的项目文档用于跨对话和跨任务交接。

以下阶段是按当前审计结果拟定的规划。阶段按依赖关系排序，具体启动和交付日期由后续任务确定。

| 阶段 | 工作方向 | 阶段完成条件 |
| --- | --- | --- |
| 项目基线 | 建立仓库地图、操作规范、决策台账和任务列表。以最近成功的部署与本地复现作为基线。 | 在 GitHub `main` 可访问五份文档，并能从文档定位内容、导航、样式和部署入口。 |
| 发布与可见性 | 确定「隐藏」文章的可见范围，统一详情页、列表、分类与订阅行为。固定经验证的 Paper 模块版本，降低重建差异。 | 隐藏策略有明确验收标准，覆盖 HTML、导航、RSS、sitemap 和公开源码。干净工作副本能解析相同的主题版本并完成生产构建。 |
| 阅读体验 | 修复分类与标签页缺失样式，完善导航键盘操作。核对中文日期和分页文案。 | 分类卡片、桌面和移动导航、浅色与深色、嵌套页面的链接与资源通过回归检查。 |
| 持续维护 | 按当前文章习惯发布内容。有图片需求时确定资源组织方式。结合维护窗口处理构建提示和经确认的冗余。 | 发布流程可复用，现有 URL 有连续性。已确定的技术变化同步写入项目地图和决策台账。 |

## 文档协作

- 每个执行任务开始时读取 [TASKS.md](TASKS.md) 和相关决策。发现新的问题时记录证据、影响和下一步。
- 已确认的技术和设计决定写入 [DECISIONS.md](DECISIONS.md)。文件用途、模板关系和可复验行为写入 [PROJECT_MAP.md](PROJECT_MAP.md)。
- 本路线图随阶段目标和优先次序变化更新。任务状态及验收记录以 [TASKS.md](TASKS.md) 为准。
